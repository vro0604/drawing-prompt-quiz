このプロジェクトの全体像と、今いる地点を出してください。作業は始めないでください。

/next との違い: /next は次の1手を出す。これは全体の中の位置を出す。
足元ではなく地図を描く。

## 1. 読むもの

次の順で読む。無いものは飛ばす。全文を読まない。

- `docs/00_IDEA.md` があれば先頭50行。ゴールの定義として使う。
- README.md があれば先頭50行。何を作るものかの宣言として使う。
- PROGRESS.md があれば、新しい方から3エントリ分。
- BACKLOG.md があれば、見出し行だけ拾って件数を数える。
- git リポジトリなら `git log --oneline -20` と `git status --short`。
- ディレクトリ構成を Glob で1〜2階層だけ見る。中身は開かない。

これ以外のファイルは読まない。中身を確かめたくなったら、読まずに
「未確認」と書く。

## 2. 段階の決め方

段階は勝手に発明しない。次の順で探す。

1. `docs/00_IDEA.md` や README.md に、作る順番・段階・マイルストーンが
   書かれていれば、それをそのまま段階として使う。出所を明記する。
2. PROGRESS.md の記述から段階が読み取れれば、それを使う。出所を明記する。
3. どちらも無い場合だけ、下の汎用の段階を使う。使うときは必ず
   「段階の定義は暫定（私が設定）。プロジェクト側の定義がありません」と
   1行書く。そしてこの段階を基準に「遅れている」「足りない」と判定しない。

汎用の段階（暫定・私が設定）
- 構想 — 何を作るかがまだ言葉の段階
- 仕様 — 何を作るか決まった。着手前
- 骨組み — 動くが中身が入っていない
- 主要機能 — 中心になる機能が動く
- 周辺機能 — 細部が埋まる
- 仕上げ — 不具合の修正と表示の調整
- 完成 — 使える

## 3. 出力の形式

作っているもの
- 1〜3行。何を作っているか。
- 出所を1行。「出所: docs/00_IDEA.md 冒頭」のように書く。
- 出所が見つからなければ「ゴールが文書化されていません」と書く。
  会話やコードから推測して埋めない。

段階と現在地
- 段階を上から順に並べ、各行の頭に状態を置く。
  「済 / 進行中 / 未着手 / 不明」の4つだけを使う。パーセントを書かない。
- 各行の後ろに、そう判定した根拠を1つ書く。実際に見たものだけ書く。
  ファイルの有無、コミットの内容、PROGRESS.md の記述。
  根拠が無い段階は「不明（根拠なし）」と書く。推測で埋めない。
- 現在地の行に「← いまここ」と付ける。

いまの位置
- 今どの段階のどこにいるか。1〜3行。
- 直前に終わったことと、その段階に残っていることを書く。

完成までに残っているもの
- 段階ごとに、残っている作業を書く。
- 分からない段階は「未定」と書いて、埋めるために推測を足さない。
- BACKLOG.md があれば、その件数をここに1行入れる。

詰まりの位置
- 前に進めなくしているものがあれば、それがどこかを書く。
- 無ければ「なし」と書く。

判断が要る分岐
- 進む方向が複数ある地点を挙げる。各分岐に推奨を1つ、理由を1行。
- 「どちらでも」と書かない。
- 無ければ「なし」と書く。

## 引数

「$ARGUMENTS」に範囲が書かれていれば、そこに絞って地図を描く。
空ならプロジェクト全体を対象にする。

## 守ること

- パーセントを書かない。測っていない数字を出さない。
- 自分で決めた段階の定義を基準に、不合格の判定を出さない。
- 読んでいないものを「済」にしない。根拠が無ければ「不明」と書く。
- コードを書かない。修正もしない。地図を描くだけ。
- 前置き・感想を付けない。「作っているもの」から始める。

判定: この出力だけを見た人が、完成までの道のりと今の位置を、
自分の言葉で説明できるか。
