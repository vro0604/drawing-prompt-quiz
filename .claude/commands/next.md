description: PROGRESS.md を読んで、現在地と次の作業を一括で示す
argument-hint: [補足・方針の変更・BACKLOG の番号（省略可）]
---

作業を再開します。次に何をするかを示してください。まだ作業は始めないでください。

## 手順

1. リポジトリ直下（git リポジトリでなければ現在の作業ディレクトリ直下）の
   PROGRESS.md を読む。無ければ「PROGRESS.md がありません」と1行だけ書き、
   作るかどうかを聞いて止まる。勝手に作らない。
2. 同じ場所に BACKLOG.md があれば読む。無ければ何もしない。
3. git リポジトリなら `git status --short` と `git log --oneline -5` を実行する。
   これ以外のコマンドは実行しない。
4. 下の形式で、1回の応答にまとめて出力する。分割しない。

## 出力の形式

現在地
- 前回どこまで終わったか。1〜3行。動作の変化が分かる言葉で書く。
  関数名・ファイル名の羅列にしない。

次の一手
- 1つだけ書く。「最初に開くファイル」と「そこで何をするか」を具体的に書く。
- 候補が複数あるなら推奨を1つ選び、理由を1行付ける。「どれもあり」と書かない。

その後の順番
1.
2.
3.
- 分かる範囲で番号を振る。分からなくなった時点で「ここから先は未定」と書いて
  打ち切る。埋めるために推測を足さない。

未確定
- 承認待ちの提案、判断が要る点を列挙する。無ければ「なし」と書く。
- PROGRESS.md に書かれていない私の推測を、この欄に混ぜない。混ぜるなら
  「提案（未承認）」と明記する。

棚上げ
- BACKLOG.md にある項目の件数を1行で書く。「棚上げ: N 件（BACKLOG.md）」
- そのうち影響が大きいと思うものを3件まで、番号とタイトルだけ挙げる。
  詳細は書かない。ファイルにある。
- 選んだ理由を全体で1行。
- BACKLOG.md が無い、または項目が0件なら「棚上げ: なし」と1行だけ書く。

引っかかり
- 前回詰まっていた点、エラー、環境側の問題。無ければ「なし」と書く。

食い違い
- PROGRESS.md の記述と、実際のファイルやコミットの状態がずれていれば書く。
  ずれが無ければ、この項目ごと省略する。

## 引数

「$ARGUMENTS」の扱いは3通り。

- BACKLOG の番号（B-003 のような形）が書かれていれば、その項目を「次の一手」に
  据える。BACKLOG.md からその項目の内容を読み、「着手前に決めること」が
  「なし」でなければ、それを「未確定」欄に出す。
- 補足や方針変更が書かれていれば、それを踏まえて「次の一手」を組み直す。
- 空なら PROGRESS.md のとおりに進める。

## 守ること

- PROGRESS.md、BACKLOG.md、上記2つの git コマンドの出力以外は読まない。
  中身を確かめたくなったファイルは、読まずに「次の一手」で対象として
  名指しするに留める。
- コードを書かない。この時点では着手しない。示して止まる。
- 前置き・感想を付けない。「現在地」から始める。

判定: これを読んだ直後に、迷わず最初の1手を始められるか。
