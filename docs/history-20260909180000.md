### どうしてこうなったか（推定）

`scripts/db-apply-one.mjs` は「当てたあと `migration repair <版> --status applied` で記録する」運用で、
repair は手元のその版のファイルから name と文を作る（4 で実測）。9/9 に profile_rpc_revoke_anon を当てた後、
同じ版番号に課金の下書きがある作業木で repair を流した、と考えると全部の事実が合う。
ただし、今の 6d24ec1 のファイルで repair すると 111文になり、本番の106文とは一致しない

106文になった下書きは git に残っていないので、**原因は推定のまま**。
