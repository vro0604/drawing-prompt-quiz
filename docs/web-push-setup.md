# ブラウザのプッシュ通知を有効にする手順（2026-09-09）

この文書のとおりにしなくても、サイトは動きます。設定しない場合、
知らせは画面の中にだけ出ます（DB には必ず残るので、見逃しても消えません）。
設定すると、サイトを閉じていても端末に通知が届くようになります。

## 何が要るか

外部の業者は要りません。要るのは鍵1組だけです。

ブラウザの製造元（Google / Apple / Mozilla）は、それぞれ自分の通知の中継所を
持っています。通知はそこへ HTTP で投げます。中継所は「誰からの通知か」を
確かめてから端末へ配るので、送り主を示す印章が要ります。これが VAPID の鍵です。

鍵は公開鍵と秘密鍵の2つで1組です。公開鍵は誰に見せてもかまいません。
秘密鍵は人に渡しません。

## 1. 鍵を作る

    node scripts/gen-vapid.mjs

画面に4行出ます。**この道具は、どこにも保存しませんし、どこへも送りません。**
出た値をコピーしてください。

## 2. 貼る

Vercel のプロジェクト → Settings → Environment Variables に4つ入れます。

| 名前 | 中身 | 誰が読めるか |
|---|---|---|
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | 公開鍵 | ブラウザにも渡る（そういうもの） |
| `VAPID_PUBLIC_KEY` | 同じ公開鍵 | サーバーだけ |
| `VAPID_PRIVATE_KEY` | 秘密鍵 | サーバーだけ |
| `VAPID_SUBJECT` | `mailto:` ＋ 自分のアドレス | サーバーだけ |

`VAPID_SUBJECT` は「この通知は誰が出しているか」の連絡先です。ブラウザの
製造元（Google / Apple / Mozilla）のサーバーが、配れない宛先が続いたときに
連絡する先として使います。**利用者には見えません。**
`mailto:` で始める形を推しますが、`https://` で始まる連絡先ページでも構いません
（`npm run check:env` はどちらも通します）。

`VAPID_PRIVATE_KEY` に `NEXT_PUBLIC_` を付けないでください。付けると
ブラウザに埋め込まれ、誰でも読めます（`npm run check:env` がこれを見張っています）。

手元で試すときは `.env.local` に同じ4行を書きます。
`.env.example` には**本番の値を書かないでください**（このファイルは共有されます）。

## 3. 確かめる

    npm run check:env

「[任意]」の欄に4つとも `✓` が付けば読めています。

## 利用者から見た流れ

1. お題を引いて制作を始める
2. 制作の画面に「制作時間やお題の期限を通知しますか？」が出る
3. 「通知を受け取る」を押すと、そこで初めてブラウザの許可の窓が開く
4. 許可すると、その端末とブラウザの宛先が保存される

**サイトを開いた直後に許可を求めることはありません。**理由が分からないまま
断られると、あとから戻すのに利用者がブラウザの設定を開く必要が出るためです。
断られても、制作・投稿・延長はこれまでどおり使えます。

## 何が送られるか

3つだけです。

- 制作予定時間を超過したとき（失敗ではありません）
- 制作途中のお題が1日間操作されていないとき
- 2日間の放置で自動的に破棄したとき

通知にお題の語や答えは1文字も入りません。通知はロック画面にも出るためです。

延長できたことは、押したその場で画面に出るので、プッシュは送りません。

## いつ送られるか

1日1回の掃除（Vercel Cron `/api/cron/cleanup`）が回ったときです。
したがって「24時間ちょうど」に届くわけではなく、最大で約24時間遅れます。
**破棄の判定そのものは DB 側で正確に48時間**として持っているので、
掃除が遅れても「48時間より早く消える」ことはありません。

より正確に届けたい場合は `vercel.json` の cron を1時間ごとへ変えます。
この変更は今回行っていません（勝手に実行回数を増やさないため）。

## 鍵を作り直したとき

秘密鍵を差し替えると、いま保存されている宛先はすべて無効になります。
利用者は通知を受け取り直す操作が必要です（画面の案内がまた出ます）。
無効になった宛先は、送信が 404 / 410 を返した時点で自動的に止まります。

## 対応していないブラウザ

案内そのものが出ません。プッシュに対応していない環境では、
知らせは画面の中にだけ出ます。**出来事は DB に残っているので、
プッシュが使えない人にも必ず伝わります。**
