# 2026-08-31 明るい地に固定した画面で、主色をどう決めているか

今日調べたのは、明るい地（白または紙のような薄い色）に固定した実在のサービスや配色の決まりごとが、
主色（主ボタンとリンクに使う1色）として何をどの値で選び、その値をどう正当化しているか。

これを選んだ理由は、docs/PENDING.md の 2 番「主色を何にするか」が
「1 番が決まってから考える」で保留のままで、その 1 番（紙・掲示板寄りで進める）が
2026-08-27 に決まったのに、出し直しがまだ行われていないため。

## 先に断っておくこと（読めた範囲）

見ていないものを見たことにしないために、今日の環境で何が読めて何が読めなかったかを先に書く。

- ページを開いて中身を読む道具（WebFetch）は、試した宛先がすべて遮断された。
  実際に試して遮断されたのは design.digital.go.jp 、smarthr.design 、zenn.dev 、
  en.wikipedia.org 、www.w3.org の5件。コマンド側（curl）も同じく通らなかった。
  よって、この報告に出てくる URL のうち、ウェブページのものは
  1つも開いていない。開いていないものは各事例に「検索結果の説明文だけ」と書く。
- 検索そのものは通った。検索が返す説明文（検索結果に付く要約）は読めている。
- GitHub の公開リポジトリ（配布元の置き場）の複製は通った。
  色の値がソースに書いてあるものは、複製して原本を直接読んだ。
  読んだ版が後から動かないよう、各事例に commit（その時点の版を指す番号）と日付を書く。
- 画像・スクリーンショットは1枚も見ていない。よって「見た目の印象」は書かない。
  書くのは、ソースに実際に書かれている値と文、それと自分で計算した数値だけ。
- 集めた事例は8件。うち6件はソースを直接読んだもの、2件は検索結果の説明文だけのもの。

## 事例

### 1. GOV.UK Design System（英国政府の共通デザイン）

- 出所: https://github.com/alphagov/govuk-frontend
  （読んだ版 fbf045a 、2026-08-27。ファイルは
  packages/govuk-frontend/src/govuk/settings/ の _colours-palette--internal.scss と
  _colours-functional.scss）
- 何をしているか: 色を「役目の名前」で定義していて、生の値を直接使わせない。
  ブランド色は青 #1d70b8 、本文は黒 #0b0c0c 、本文の地は白 #ffffff 。
  リンクだけはブランド青そのものではなく、1段暗くした #1a65a6 を当てている。
  ページの枠（ヘッダーやフッター）の地は、青をごく薄めた #f4f8fb 。
  キーボードで今どこにいるかを示す色は黄 #ffdd00 で、その上の文字は黒。
  暗い側の切り替え（prefers-color-scheme）は、ソース全体に1か所も無い。
- なぜそうしていると思われるか: リンクを1段暗くしているのは、白地で文字として
  読める濃さ（後述の 4.5:1）を確保するためと思われる。実測すると
  #1d70b8 は白地で 5.17 、#1a65a6 は 6.08 で、余裕が広がっている。
  印刷用の文字色だけ真っ黒 #000000 にしてあり、ソースに
  「プリンタが本文を色インクで刷らないように真っ黒を使う」と理由が書いてある。
- このプロジェクトに当てはめるなら: 主色を1つ決めたあと、リンクにはその色を
  そのまま使わず、1段暗くした値を別に持つ。いまの globals.css は色を
  役目の名前（--accent 、--on-accent 、--line など）で持っているので、器はもうある。
  足りないのは「リンク用に1段暗い値」の枠だけ。
- 当てはめない方がよい点: 青と黄の組み合わせは英国政府の看板そのもので、
  紙・掲示板寄りにしたいこのサービスには強すぎる。借りるのは色ではなく、
  「ブランド色とリンク色を別の値にする」という組み方の方。

### 2. デジタル庁デザインシステムのデザイントークン

- 出所: https://github.com/digital-go-jp/design-tokens
  （読んだ版 cde7dfe 、2026-05-28。ファイルは figma/tokens.json）
  説明ページは https://design.digital.go.jp/dads/foundations/color/ にあるが、
  今日は開けていない（遮断された）。
- 何をしているか: 色を3層に分けている。素の色（Primitive）が10系統、
  無彩色（Neutral）が白・黒・SolidGray など、意味を持つ色（Semantic）が
  成功・エラー・注意の3つ。そして主色（Key）は青の各段への参照として定義され、
  独立した値を持たない。成功は緑の 600（#259d63）と 800（#197a4b）、
  エラーは赤の 800（#ec0000）と 900（#ce0000）。青は 50（#e8f1fe）から
  1200（#000060）まで13段。
- なぜそうしていると思われるか: 灰色の段に 420 と 536 という半端な番号がある。
  値は #949494 と #767676 で、白地に対する比を計算すると 3.03 と 4.54 。
  部品に必要な 3:1 と、文字に必要な 4.5:1 のちょうど境目に置いた段だと思われる。
  検索結果の説明文にも「テキストとして使う場合は 4.5:1 以上、
  コンポーネントに使う場合は 3:1 以上」と書かれていた。
- このプロジェクトに当てはめるなら: 主色を1つの値ではなく、濃さの段として持つ。
  そうすると「ボタンの地に使う段」と「文字に使う段」を別々に選べる。
  正解・不正解の色も、主色とは別系統（緑と赤）から取る前例がここにある。
- 当てはめない方がよい点: 13段は多すぎる。この規模のサービスで13段作っても
  使い分けられず、いまの globals.css が「文字の濃さを3段しか作らない」と
  決めた判断（薄い灰色で階層を作らない）と正面からぶつかる。段は2つか3つでよい。

### 3. Excalidraw（手書き風の絵を描く道具）

- 出所: https://github.com/excalidraw/excalidraw
  （読んだ版 e1bb9ff 、2026-08-26。ファイルは packages/common/src/colors.ts と
  packages/excalidraw/appState.ts）
- 何をしているか: 描く色の既定は真っ黒ではなく #1e1e1e 。
  画布（絵を描く面）の既定は白で、選べる地の候補が白のほかに4つある。
  #f8f9fa 、#f5faff 、#fffce8 、#fdf8f6 の4つで、いずれも白からごくわずかに
  ずらしただけの色（白との比は 1.05 前後）。ソースの注釈に
  radix の slate2 / blue2 / yellow2 / bronze2 と、借りた出所が書いてある。
- なぜそうしていると思われるか: 絵が主役の画面なので、地に色を持たせすぎると
  絵の色と喧嘩する。かといって真っ白だと固いので、気づかれない程度に温度だけ
  足していると思われる。線の色を真っ黒でなく #1e1e1e にしているのも同じ方向で、
  紙に鉛筆やペンで引いた線に近づけるためと思われる。
- このプロジェクトに当てはめるなら: 紙の地を作るとき、白から離れすぎないこと。
  この4つのうち #fdf8f6 のような、白との比が 1.05 程度の色を地に取る。
  絵が主役という点はこのサービスと同じ条件なので、そのまま持ってこられる。
- 当てはめない方がよい点: 無し。ただし「地を選ばせる」ところまでは要らない。
  こちらは1つに固定して構わない。

### 4. PaperCSS（紙に手書きしたような見た目の CSS の型）

- 出所: https://github.com/papercss/papercss
  （読んだ版 b341c16 、2025-06-23。ファイルは src/core/_config.scss）
- 何をしているか: 名前のとおり紙・手書き寄りの見た目を作る部品集。
  ここで注目したのは、主色（$primary）に色を当てていないこと。
  値は #41403e で、これは黒に少し茶を混ぜた墨のような色。
  色みを持つ青 #0b74d5 は副色（$secondary）の側に置かれている。
  書体は Neucha と Patrick Hand SC という手書き風のものを外から読み込んでいる。
- なぜそうしていると思われるか: 紙の見た目では、いちばん強い色が「インクの色」に
  なるのが自然で、色みのある色は補助に回る、という判断だと思われる。
  #41403e は白地で 10.36 と濃く、本文にもボタンの地にも使える濃さがある。
- このプロジェクトに当てはめるなら: 主色を「色を選ぶ」問題ではなく
  「インクを何色にするか」の問題として扱う道がある。いまの --accent は
  真っ黒 #000000 なので、これを #41403e や #1e1e1e のような墨に寄せるだけでも
  紙らしさは出る。そのうえで、色みは1か所（たとえばリンクか、正解の印）にだけ置く。
- 当てはめない方がよい点: 手書き風の書体は、日本語では選択肢がほとんど無く、
  読み込む量も大きい。2026-08-27 に Noto Sans JP と決めた判断を覆す理由にはならない。

### 5. Tufte CSS（本の組版を web に持ち込んだ型）

- 出所: https://github.com/edwardtufte/tufte-css
  （読んだ版 b5d7b7b 、2026-06-25。ファイルは tufte.css の 53 行目から 63 行目）
- 何をしているか: 地を #fffff8 、文字を #111 にしている。
  #fffff8 は白から黄側へごくわずかにずらした色で、白との比は 1.01 未満。
  そのすぐ下に暗い側の切り替えがあり、暗いときは地 #151515 、文字 #ddd に変わる。
- なぜそうしていると思われるか: 紙の白は純白ではないので、黄側へ少しだけ
  ずらすと紙に近づく、という考えだと思われる。文字を真っ黒でなく #111 に
  しているのも同じ方向。
- このプロジェクトに当てはめるなら: 地の候補として #fffff8 のような
  黄側のずらし方も取れる。事例3の #fdf8f6（赤側のずらし）と並べて、
  どちらの温度にするかを選ぶ材料になる。
- 当てはめない方がよい点: この型は暗い側の切り替えを持っている。
  こちらは 2026-08-27 に「明るい側に固定」と決めているので、
  そこは真似しない。真似すると決定 4 を壊す。

### 6. Radix Colors（色の段を作るための決まりごと）

- 出所: https://github.com/radix-ui/colors
  （読んだ版 dbdb854 、2025-12-17。ファイルは src/light.ts）
- 何をしているか: 色を系統ごとに12段で持つ。紙に近い温かい無彩色の系統が
  sand で、いちばん薄い sand1 が #fdfdfc 、いちばん濃い sand12 が #21201c 。
  青は blue9 が #0090ff 、blue11 が #0d74ce と、同じ青でも役目ごとに段が違う。
- なぜそうしていると思われるか: 9 番は「面を塗る色」、11 番は「文字に使う色」と
  役目が段ごとに決まっているためと思われる。実測すると blue9 は白地で 3.26 で
  文字には足りず、blue11 は 4.77 で足りる。この差が段の役目の違いに対応している。
- このプロジェクトに当てはめるなら: 紙の地の候補として sand1 #fdfdfc が使える。
  また、主色を決めるときに「面用」と「文字用」で別の値を持つ根拠になる。
- 当てはめない方がよい点: ここで重要な落とし穴が1つある。
  blue11 #0d74ce は白地では 4.77 で足りているが、紙の地 #faf8f3 に置くと 4.49 で
  4.5 をわずかに割る（自分で計算した値）。事例2の #767676 も、白地 4.54 が
  紙の地では 4.28 に落ちる。純白を前提に選ばれた値は、地を紙色に変えた瞬間に
  基準を割ることがある。借りるなら、借りた先の地ではなくこちらの地で計算し直すこと。

### 7. note（文章を書いて公開するサービス）

- 出所: https://www.help-note.com/hc/ja/articles/900001287623-note%E3%81%AE%E3%83%86%E3%83%BC%E3%83%9E%E3%82%AB%E3%83%A9%E3%83%BC%E3%81%AE%E8%A8%AD%E5%AE%9A
  このページは開けていない。検索結果の説明文だけを読んだ。
- 何をしているか: 検索結果の説明文によると、法人向けの機能でボタンやリンクの色を
  変えられ、その既定値が「note で使っているグリーン #238F76」とのこと。
  値そのものは検索結果の説明文に書かれていた。
- なぜそうしていると思われるか: 白い地に文章が並ぶサービスで、

- このプロジェクトに当てはめるなら: 参考になるのは色そのものより、

- 当てはめない方がよい点: 値そのものは、開けていないページの説明文が出所なので、
  採用するなら人の側で実際の画面を見て確かめること。

### 8. Cosense（旧 Scrapbox 、書いたものをつなげる道具）

- 出所: https://scrapbox.io/forum-jp/%E3%83%9A%E3%83%BC%E3%82%B8%E3%81%AE%E8%83%8C%E6%99%AF%E8%89%B2%E3%82%92%E5%A4%89%E3%81%88%E3%82%89%E3%82%8C%E3%82%8B%E3%82%88%E3%81%86%E3%81%AB%E3%81%97%E3%81%A6%E6%AC%B2%E3%81%97%E3%81%84%E3%80%82
  このページは開けていない。検索結果の説明文だけを読んだ。
- 何をしているか: 検索結果の説明文によると、文字に色を付ける機能を意図的に
  持たせていない。代わりに、リンクがいちばん目立つように作られている。
  既定では、中身のあるリンクは青、まだ中身の無いリンクは橙で表示されるとのこと。
- なぜそうしていると思われるか: 色を1つの意味にだけ使うと決めておくと、
  色が付いている＝行き先がある、と読めるようになる。色を自由に使えるようにすると
  この読み方が崩れる。それを避けた判断だと思われる。
- このプロジェクトに当てはめるなら: このサービスで色を持たせる先は多くない。
  絵が主役なので、色を持つのは「押せるもの」と「当たり外れ」の2つに限ってよい。
  逆に、見出しや飾りに主色を散らすと、絵と取り合いになる。
- 当てはめない方がよい点: 「中身が無いものを橙」の使い分けは、こちらには対応物が
  無い。真似するところではない。

## 計算した表

以下はこの場で計算した値で、どこかから引いてきたものではない。
コントラスト比（2つの色の明るさの差を表す数値。大きいほど読みやすい）は
WCAG の式で求めた。本文の文字は 4.5 以上、ボタンの枠のような部品は 3.0 以上が目安。

### 主色の候補が、地に対してどれだけの比になるか

| 色 | 白 #ffffff | 生成り #fdf8f6 | 紙 #faf8f3 | 白い文字をのせたとき |
|---|---|---|---|---|
| 藍 #1b3a5c（PENDING 2 の答え方の例） | 11.63 | 11.04 | 10.95 | 11.63 |
| 墨 #1e1e1e（Excalidraw） | 16.67 | 15.83 | 15.71 | 16.67 |
| 墨 #41403e（PaperCSS） | 10.36 | 9.83 | 9.76 | 10.36 |
| 青 #1a65a6（GOV.UK のリンク） | 6.08 | 5.77 | 5.73 | 6.08 |
| 青 #1d70b8（GOV.UK のブランド） | 5.17 | 4.91 | 4.87 | 5.17 |
| 青 #0017c1（デジタル庁 Blue.900） | 11.10 | 10.53 | 10.45 | 11.10 |
| 青 #0b74d5（PaperCSS の副色） | 4.69 | 4.46 | 4.42 | 4.69 |
| 緑 #238f76（note） | 3.99 | 3.79 | 3.76 | 3.99 |
| 臙脂 #9b2f2f | 7.39 | 7.02 | 6.96 | 7.39 |
| 朱 #d64b2a | 4.29 | 4.07 | 4.04 | 4.29 |
| 現状の黒 #000000 | 21.00 | 19.93 | 19.79 | 21.00 |

読み取れること。

- 地を白から紙色に変えると、比は 5 パーセントほど下がる。少しだが、
  もともと 4.5 ぎりぎりだった色は割る。#0b74d5 は白地 4.69 が紙地 4.42 になり、
  文字として使えなくなる。
- 藍 #1b3a5c は紙地でも 10.95 あり、文字にもボタンの地にも使える。
  白い文字をのせても 11.63 で足りる。両方に使える候補はこの濃さの帯にある。
- 朱や緑のような明るい色は、紙地で 4 前後にしかならない。
  ボタンの地には使えるが、リンクの文字色には使えない。

### いまの globals.css の薄い文字が、地を紙色にしたときどう動くか

いまの src/app/globals.css は、文字の濃さを黒の不透明度で3段だけ作っている。
地を白から紙色に変えると、これらの比も動く。実際に計算した。

| 変数 | 白 #ffffff | 紙 #faf8f3 | 生成り #fdf8f6 |
|---|---|---|---|
| --muted 黒 70% | 8.45 | 8.33 | 8.36 |
| --faint 黒 55%（現在の下限） | 4.74 | 4.68 | 4.68 |
| --decor 黒 25%（飾りだけ） | 1.83 | 1.83 | 1.83 |

読み取れること。

- 下限に置いた --faint は、紙の地に変えても 4.68 で 4.5 を割らない。
  つまり、地を紙色に変えても、いまの文字の3段はそのまま使える。
  この点で、地を変える作業は文字の設計をやり直す作業を連れてこない。
- ただし余裕は 0.18 しか無い。地をこれ以上暗くする（たとえば白との比が
  1.1 を超える紙色にする）と割る。紙色は白との比 1.05 前後までに収めること。
- 計算では、黒を重ねた結果の色を整数に丸めている。ファイルの注釈にある 4.76 と
  ここでの 4.74 の差はその丸めによるもので、判断は変わらない。

## 判断が要る点

### 1. 主色を何にするか（PENDING 2 の出し直し）

2026-08-27 に「1 番は a（紙・掲示板寄り）」と決まったので、保留にしていたこれを出し直す。
いまは --accent が真っ黒 #000000 。

- 選択肢:
  - (a) 色みを持たせず、墨に寄せる。--accent を #1e1e1e か #41403e にする。
    色みのある色は使わない。
  - (b) 藍 #1b3a5c を主色にする。ボタンの地にもリンクの文字にも1つの値で足りる。
  - (c) 明るい色（朱 #d64b2a や緑 #238f76 など）を主色にする。
    この場合、リンクの文字色には別の濃い値をもう1つ決める必要がある。
  - (d) 別の値を指定する（値をください）。
- 推奨: (b)。紙の地でも 10.95 あり、白い文字をのせても足りるので、
  ボタンとリンクを1つの値でまかなえる（事例6の落とし穴を踏まない）。
  真っ黒からの変化も分かる。(a) は安全だが、紙・掲示板寄りにしたときに
  「押せるもの」と「ただの文字」の区別が濃さだけになる。
- 答え方: 「2: a #1e1e1e」「2: b」「2: c #d64b2a」「2: d #445566」

### 2. 地を白のままにするか、紙色にするか

- 選択肢:
  - (a) 白 #ffffff のまま。地は変えず、紙らしさは線と余白と書体で出す。
  - (b) 紙色にする。候補は #fdf8f6（赤側・Excalidraw が使っている）、
    #fffff8（黄側・Tufte CSS）、#fdfdfc（ほぼ無彩色・Radix sand1）。
  - (c) もっと濃い紙色にする（値をください）。
- 推奨: (b) の #fdf8f6 。上の計算のとおり、この濃さなら文字の3段が
  そのまま使える。事例3が「絵が主役の画面」という同じ条件で選んでいる値でもある。
- 答え方: 「地: a」「地: b #fdf8f6」「地: c #f5efe6」

### 3. 当たり外れの色を、主色と分けるか

このサービスは当たり外れを見せる画面がある。その色を主色と同じにするか分けるか。

- 選択肢:
  - (a) 分ける。正解は緑、外れは赤（または灰）。デジタル庁の
    Green.600 #259d63 と Red.800 #ec0000 が、白地で計算済みの前例。
  - (b) 分けない。当たりも主色で示し、外れは色を使わず薄さだけで示す。
  - (c) 色を使わず、印（丸と罰、文言）だけで示す。
- 推奨: (a)。ただし文字に使うなら濃い方の段（Green.800 #197a4b 、Red.900 #ce0000）を
  取ること。計算した値は次のとおりで、薄い方の段は文字には使えない。

  | 色 | 白 #ffffff | 紙 #fdf8f6 |
  |---|---|---|
  | Green.600 #259d63 | 3.45 | 3.28 |
  | Green.800 #197a4b | 5.35 | 5.08 |
  | Red.800 #ec0000 | 4.60 | 4.37 |
  | Red.900 #ce0000 | 5.79 | 5.50 |

  赤の #ec0000 は白地では 4.60 で通るのに、紙の地では 4.37 で割る。
  事例6で書いた落とし穴が、ここでも実際に起きている。
  色だけに頼らないよう、(c) の印も併せて置くとよい。
- 答え方: 「当たり外れ: a」「当たり外れ: b」「当たり外れ: c」
