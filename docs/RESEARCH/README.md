# 調査の置き場

平日の日中に走る無人実行は、このフォルダへ調査レポートを
`YYYY-MM-DD_題材の短い名前.md` という名前で書きます。1回の起動につき1本です。

## このリポジトリでの位置づけ

このプロジェクトの無人実行は調査専用です。コードを一行も変えません。
実装は ユーザー が手で行い、無人実行は判断材料を外から集めてくる側に回ります。

出所: ユーザー発言「実装の一本化とそれ以外のプロジェクトに使うリサーチの豊富化を
行いたい」（2026-08-30）。実装を1本に絞ったのは、週あたりの利用制限に対して
実装2本の同時進行が重いと分かったため。

## 題材の範囲

見た目と使い勝手が中心。紙・掲示板寄りの質感（2026-08-27 に確定）へ寄せるための事例、
投稿と閲覧が混ざるサービスの画面の組み方、限定公開の運用、絵を主役にした配色と余白の取り方、
選択式のクイズの出し方、当たり外れの見せ方。
実装の判断材料になるものだけを集める。技術の一般論は集めない。

## 1本の書き方

先頭に、今日何を調べたのかを1行。次に、なぜそれを選んだかを1行。

そのあと事例を1件ずつ、次の5行で書く。

- 名前と出所（URL）
- 何をしているか。2から3行。
- なぜそうしていると思われるか。推測なら推測と書く。
- このプロジェクトに当てはめるならどうなるか。具体的に、1から2行。
- 当てはめない方がよい理由があれば、それも1行。

最低5件、多くて10件。見ていないものを見たことにしない。開けなかったページが
あれば、そのことを冒頭に書く。図や画像は URL を書くだけにして、
ダウンロードしてリポジトリに入れない。

最後に「判断が要る点」を3件以内。選択肢と、推奨と理由を1行、
そのまま返せる短い答え方を書く。
