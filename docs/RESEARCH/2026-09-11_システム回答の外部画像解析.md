# システム回答に使う外部の画像解析サービス（Phase 3 調査）

今日調べたこと: システム回答（D195）を外部の画像解析サービスで作る場合の、候補・費用・情報の境目・失敗の扱い。
選んだ理由: Phase 2 で保存の道はできたが、外へ何を渡し、どこで作るかが決まっていないため。

## この記録の前提

- 調査日: 2026-09-11
- 価格・保存期間・学習への利用は、すべて調査日時点の各社の公式資料による。変わりうる
- **提供元はまだ決めていない。**実画像での精度試験の前なので、下の推奨は「第一候補」であって採用ではない
- **実画像は1枚も外部へ送っていない。**API の鍵も作っていない
- まとめ記事は使っていない。各社の公式ドキュメントだけを読んだ

## 訂正（2026-09-11、ユーザー指摘による）

最初の報告で「構造化出力のスキーマ適合を保証するのは Claude だけ」と推奨理由に書いた。
これは誤り。同じ報告の比較表で、OpenAI の strict モードも適合を保証すると書いていた。
**推奨理由から「Claude だけが保証する」を除く。**

出所: ユーザー指示（2026-09-11）「『Claudeだけがstructured outputのschema適合を保証する』
とは扱わない。報告自身の調査結果では、OpenAIのstrict structured outputもschema適合保証がある。」

## 情報の境目（確定したもの）

出所: ユーザー指示（2026-09-11）の確定事項。

外へ渡すもの:

- 作品の画像
- 設問の識別子と表示名
- 答え方（ビタ当て／2択当て）
- 4択の識別子と表示語

外へ渡さないもの:

- 正解の印・正式なお題の語
- 作者の言葉・作品タイトル
- 利用者の情報（名前・メールアドレス・ID）

返させるのは選択肢の識別子だけで、自由文は受け取らない。
正誤は Phase 2 の `save_system_answer` の中でだけ決める。

画像は、サーバーが中身を取ってから送る方式を第一候補とする。
理由: `works` バケットは公開で、公開URLは表示を止めた作品・消した作品でも
掃除が走るまで取得できる。URL を外部へ渡すと、その判断をこちらで挟めない。

## 判断が要る点

1. **提供元の最終決定。**選択肢は Claude Haiku 4.5 / Gemini 3.5 Flash-Lite / OpenAI gpt-5-nano。
   推奨は、少数の作品で3社を並べて精度を測ってから決めること。理由: 公式資料からは4択を選ぶ精度が分からない。
   答え方: 「3社で試してから決める」または「◯◯だけで試す」。

2. **1日の上限。**選択肢は 100 / 500 / 1,000件。
   推奨は 100件から始めること。理由: 本番の作品は930件で、1日100件でも全部に1件ずつ付けられる量。
   答え方: 「100件」など数字1つ。

3. **利用規約とプライバシーポリシーの改定。**外部へ1枚でも送る前に必要。
   推奨は、提供元が決まってから事業者名を入れて改定すること。理由: 本文は版ごとに DB へ入り、改定のたびに投稿者へ同意を取り直すため。
   答え方: 「提供元が決まってから」または「先に一般的な書き方で出す」。
