# 一般公開の前に残っている非課金の問題（2026-09-17 の再監査）

課金（Stripe・Founder・billing の migration・課金の規約）は対象外。別の作業線が進めている。
基準は origin/main `6a1a20b` と、その版が載った本番 https://drawing-prompt-quiz.vercel.app 。

**結論: 技術的には、まだ一般公開できない。**
コードが壊れているからではない。本番で利用者の流れは最後まで通った。
止めているのは、(1) 一般公開に切り替える判断がまだ無いこと（規約の本文と検索除外が「限定公開」のまま）、
(2) 答える作品が本物2件しか無いこと、(3) 人の手でしか確かめられない本番の設定と通報の送信が未確認なこと。

## 2. 本番で通した利用者の流れ（smoke-journey）

作者（PC 幅）: 確認メールのリンクを**別のブラウザの入れ物で**開く → 同意の画面へ送られる（版 2026-09-09）→ 同意 →
ID を決める → お題を引く → 全部めくる → 確定 → 投稿（画像つき）→ 自分の作品に「回答できません」「まだ誰も答えていません」→
共有の面（URL 欄と X への投稿。投稿文と head にお題の語が無い。og:image が 200、twitter:card は大きい画像）。

ゲスト（スマホ幅）: 共有 URL を開く → /works・/rankings・作者のプロフィールに出る → 長押しで4問に答える →
結果と「次の作品に答える」→ 再読み込みしても再回答できない → 次の作品（本物の公開作品へ移った。答えていない）。

登録者B（スマホ幅）: 回答 → 保存 → お気に入りに出る → 通報の画面に人間確認の枠 → 回答の履歴に出る。

作者: 知らせに回答が届く → 結果を開ける → プロフィールに作品 → スマホ幅で5画面 → 画面から削除 → 404 → サインアウト。

長文版（`JOURNEY_LONG=1`）: 区切りの無い英数字60字の題名・30字の表示名・20字の ID・横長の絵で同じ一周。
項目はすべて合格したが、**画面写真ではスマホの /works と /u/<ID> のカードが右へはみ出して切れていた**（B3）。
はみ出しの検出は外側で切られているため 0 と出た。数字だけで合格にしない。

片づけ: 作品は画面から削除、登録者は Admin API で削除、スモークの固定利用者27人は
`smoke:prod -- fixtures --apply --expect 27` で削除（残り0）。
残したもの: ゲスト6人（掃除 Cron の対象）、削除済みの検査作品の行、使い捨ての人の同意記録（持ち主は空）。
本物の作品2件と、メールで登録した本物の利用者4人の行指紋は、前後で同じ。

## 3. 今回直したもの（検査の道具だけ。アプリのコードは変えていない）

- `scripts/_smoke-http.mjs`: 答えの漏れを数えるときに、サイト共通のフッターを外す。
  フッターの「特定商取引法に基づく表示」に「取引」が入っており、お題に「取引」が出ると本番の smoke:work が
  漏れていないのに2件落ちていた（本番で実測）。ブラウザ試験は D205 で同じ理由で外している。
- `scripts/smoke-journey.mjs`（新規）: 上の 2。本番の入口 `smoke:prod` からだけ動く。

## 4. 見られなかったもの

- **本番のログ**（Vercel の実行記録、Supabase の API・Postgres・認証の記録）。
  Vercel CLI は未ログイン。Supabase の記録は管理 API の鍵が要り、鍵の場所を探す操作は権限で拒否された。
  代わりに見たもの: ブラウザで拾った 5xx・ページの例外・console のエラーは3回の一周と19画面×2幅で 0、
  DB の deadlock 0、知らせの配信の失敗 0、退会処理の失敗 0、画像の削除待ちの失敗 0。
- **Supabase の管理画面の設定**（匿名サインインの回数上限、確認メールの本文、バックアップ）。同じ理由。
  Confirm email が ON であることだけは、公開の設定値（`/auth/v1/settings` の `mailer_autoconfirm: false`）で確かめた。
- **通報の送信**。本番は本物の Turnstile で、自動操作では通せない（通すための抜け道は作らない）。
  確認の値が無い送信が日本語で断られることは smoke:report で確かめた。
