# 本番スモークが、自分で作った人を自分で消す（2026-09-18）

本番で画面を1周する検査（`npm run smoke:prod -- journey`）は、
これまで匿名ゲストを1回につき1人、本番に置き去りにしていた。
その1人は本番の利用者数にも、初回利用ファネル（docs/funnel-v0.md）にも混ざっていた。
この文書は、何が残っていたか・なぜ消せなかったか・どう直したか・
どこまでを保証し、どこからは保証しないかを記録する。

---

## 0. 言葉を先に決める（「利用者」と一括りにしない）

3つは意味が違う。報告では必ずどれかを名指しする。

| 呼びかた | 中身 | 2026-09-18T00:10Z の実測 |
|---|---|---|
| 認証アカウント数 | `auth.users` の行数。ログインの口に登録されている人。ゲストも含む | 40 |
| 人の行 | `public.profiles` の行数。サービス側の人の行。`auth.users` の挿入トリガーが1対1で作る | 40 |
| 観測できた行動者 | 期間で切ったときの `profiles` の件数。**ファネルの分母はこれ** | 全期間 40 ／ 30日 31 ／ 7日 8 ／ 24時間 7 |

登録済みの4人はいずれも検査用ではない（`auth.users` に検査用のメールを持つ人は0）。

3つのうち上の2つは、いまは常に同じ数になる。
`profiles` の行は `auth.users` のトリガーだけが作り、
`auth.users` を消すと `on delete cascade` で一緒に消えるため
（supabase/migrations/20260803013433_baseline_applied_schema.sql:112）。
違うのは3つめで、これは期間を切った数なので必ず小さくなる。

「利用者が何人」と書くときは、原則として3つめ（観測できた行動者）を使う。
ページを見ただけの人は、そもそもどの数にも入らない（docs/funnel-v0.md 0節）。

## 2. なぜゲストだけ消せなかったか

3つが重なっていた。

1. ゲストはスモークが作っていない。
   回答の送信をサーバーが処理するとき `ensureUserId()` が匿名サインインを起こす
   （src/features/auth/session.ts）。スモークは頼んでいないし、返事も受け取らない。
   だから**自分が誰を作ったのかを一度も知らなかった。**

2. 既存の片づけは電子メールの形で検査用を見分ける
   （scripts/_test-accounts.mjs の3つの形）。匿名ゲストは電子メールを持たないので、
   どの形にも当たらない。`npm run cleanup:testdata` も
   `npm run smoke:fixtures:purge` も対象外。

3. 定期の掃除は拾うが、条件が「作られてから30日以上たっている」。
   `list_stale_guests`（supabase/migrations/20260804120000_cleanup_jobs.sql:376）。
   つまり30日間は本番に残り、その間ずっとファネルに混ざる。
   旧スモークの冒頭に書いてあった「ゲストは掃除 Cron が拾う」は、
   30日後に拾うという意味で、今日の数字には効かない。

## 3. 新しい見つけかた（推測しない）

ゲストの ID を、**作られたその場で2つの独立した経路から拾う**
（scripts/\_smoke-actors.mjs）。

| 経路 | 何を読むか | 何に依存するか |
|---|---|---|
| 1. セッション Cookie | ブラウザの入れ物にある `sb-<ID>-auth-token` を復号し、中の access_token の `sub` を読む | Cookie の入れかた（base64 でも素の JSON でも、`.0` `.1` に割れていても読める） |
| 2. 自分の作品への回答行 | **この実行が投稿した作品**に付いた回答の `user_id` を読む | 作品を投稿できていること |

どちらも「この実行が作った物」しか見ていない。
拾った ID は、消す前に認証の口へ問い合わせて匿名であることを確かめる。
登録者の ID を拾っていたらその場で不合格にする。

使わない見分けかた（禁止）:
最近作られたゲスト全部・回答が1件だけのゲスト全部・電子メールが無い人全部・
特定の時刻範囲の人全部。どれも実利用者を巻き込む。

## 4. 消す順と、その理由

片づけは `finally` に置いてある。成功でも、assertion の失敗でも、
時間切れでも、画面遷移の失敗でも、必ず通る。

1. 作品の画像（置き場から消す）
   作品の行より先に消す。行を消すと、画像の場所を書いた列ごと無くなる。
2. 利用の記録・同意の記録（`user_id` で名指し）
   人より先に消す。人を消すと `user_id` が `null` になり、誰のものか辿れなくなる
   （どちらも `on delete set null`）。
3. 作品 → お題 → ドラフト（ID で名指し。scripts/\_smoke-own-rows.mjs）
   作品が残っているとお題を消せない（外部キー `works_prompt_id_fkey` が `restrict`）。
   回答は作品と一緒に消える（`answers.work_id` が `cascade`）。
4. 人（登録者もゲストも同じ）
   `auth.users` を消すと `profiles` が `cascade` で消え、ドラフトも道連れで消える。

## 5. 人を消したとき、何が消えて何が残るか（使い捨て環境で実測）

本物の migration を当てた使い捨ての DB（PGlite）で測った。
試験は test/tools/run.mjs の「ゲストを消すと、何が消えて何が残るかを実測する」。

| 行 | 人を消したあと | 外部キーの指定 |
|---|---|---|
| `profiles` | 消える | `auth.users` へ `on delete cascade` |
| `draft_sessions` | 消える | `profiles` へ `cascade` |
| `notification_events` / `push_subscriptions` | 消える | `auth.users` へ `cascade` |
| `answers` | **残る**（`user_id` が `null` になる） | `set null`。作品側の集計を過去に遡って減らさないため |
| `usage_events` | **残る**（`user_id` が `null`） | `set null` |
| `terms_agreements` | **残る**（`user_id` が `null`） | `set null` |
| `prompts` | **残る**（`created_by` が `null`） | `set null` |
| `works` | **残る**（`user_id` が `null`） | `set null` |

「持ち主を消せば全部消える」は成り立たない。だから新しい片づけは、
残るほうの行を**人より先に、ID で名指しして**消している。

ファネルへの影響: ファネルは `profiles` から人を数えるので、
持ち主の外れた行はどの段にも入らない。
実測では、ゲストを1人消すと母数と「1回答えた」が1ずつ減った。

## 6. 何をもって「残っていない」と言うか

スモーク自身が、一周の**前**と片づけの**後**に同じ8つを数え、
1つでも違えば不合格にする（scripts/\_smoke-baseline.mjs）。
「消しました」という返事ではなく、件数が戻ったことだけを証拠にする。

数えるのは `auth.users` / `profiles` / `draft_sessions` / `prompts` /
`works` / `answers` / `usage_events` / `terms_agreements` の8つ。
これは D209 のファネルが読む表そのもの。

## 7-b. 通信だけのスモークにも同じ穴があった（同じ日に塞いだ）

一周する検査（journey）だけの話ではなかった。
`scripts/smoke-anon.mjs` は冒頭にこう書いてある(44行目)。
「ゲスト2人と、その1人が昇格した登録ユーザー1人。作った作品は片づける。」
つまり本番で走らせるとゲストが残る。原因は同じで、ゲストを作るのはサーバー側だから。

直しかたは1か所にまとめた。すべてのスモークが共通で使う入口
（`scripts/_smoke-http.mjs`）に、開いた入れ物を控える帳面を置き、
終わりの処理（`finish()`）で各入れ物の Cookie を復号して人を消す。
スモークを1本ずつ直すのではなく、**人が生まれる経路の出口を1つにした。**

消してよい相手の決めかた（`deleteAnonymousActors`）:

| 相手 | どうするか | なぜ |
|---|---|---|
| 認証の口が「匿名」と言う | 消す | この実行が作ったゲスト |
| 匿名でないが、使い捨ての検査用のメール（`dpq-smoke-` / `dpq-probe-`） | 消す | ゲストが途中で登録に変わった場合（smoke-anon の昇格） |
| 固定の検査用利用者（`dpq-fixture-`） | **消さない** | 毎回使い回す前提の人。消すと毎回作り直しになり、匿名サインインの回数制限（1時間30回・IP単位）を削る |
| それ以外 | 消さない。理由を返して不合格にする | 実利用者を巻き込まないため |
| 相手を読めなかった | Cookie が匿名と言っていたときだけ消しにいく | 読めないことを「消してよい」に読み替えない |

本番で `npm run smoke:prod -- anon` を1回流した実測（2026-09-18）:
匿名ゲスト3人を消した。ただし固定の検査用利用者2人は上の表のとおり残る（設計どおり）。
消すには別のコマンド `npm run smoke:fixtures:purge` が要る。

その2人を本番向けの入口で消したときの実測（2026-09-18T00:10Z）。
**既存の purge は利用者を消すだけで、行は消さない。**外部キーの指定どおりに分かれた。

| この2人が持っていた行 | どうなったか | なぜ |
|---|---|---|
| ドラフト 2件 | 消えた | `draft_sessions.user_id` は `profiles` へ `on delete cascade` |
| 確定したお題 2件 | 残って持ち主が外れた | `prompts.created_by` は `set null` |
| 作品 2件 | 残って持ち主が外れた | `works.user_id` は `set null`。どちらも先に画面から削除済み・非公開なので、一覧にも検索にも出ない |
| 同意の記録 4件 | 残って持ち主が外れた | `terms_agreements.user_id` は `set null` |
| 回答・利用の記録 | 0件（持っていなかった） | この一周で答えたのは匿名ゲストのほうで、そちらはスモークが自分で消している |

持ち主の外れた行はファネルのどの段にも入らない（5節）。
消す前に、消してよい相手かを8項目で独立に確かめた（対象ちょうど2人／2人とも固定の検査用／
残す40人が1人も含まれない／匿名ではない／fixture 以外が0／残す側に検査用のメールが0／合計が一致）。
`--dry-run` の結果（対象2人・残す40人・全体42人）とも一致した。

## 8. 保証する範囲と、しない範囲

保証する:
- 正常終了したとき、この実行が作った人・作品・お題・ドラフト・
  利用の記録・同意の記録・画像が本番に残らない。
- 途中で止まったときも、そこまでに作った物について同じ。
- 片づけに失敗したら、スモーク全体を不合格にして終了コード1で終わる。
  黙って成功にしない。

保証しない:
- `kill -9`・端末ごとの強制終了・停電など、`finally` 自体が走らない場合。
  このときは作った物が残る。残ったゲストは30日後に定期の掃除が拾う
  （`list_stale_guests`）。それより早く消したいときは、
  そのときの出力に出ている ID を使って手で消すしかない。
- 本番の Supabase に届かない状態（鍵切れ・停止中）での片づけ。
  この場合は「消せなかった」と出して不合格になる。
- この実行より前に残ったもの。過去の検査データの片づけは別の作業
  （`npm run cleanup:testdata`）。
- 固定の検査用利用者（`dpq-fixture-…@dpq-smoke.invalid`）。使い回す前提なので残す。
  本番のファネルでは「登録済み」として数えられるので、
  本番で通信のスモークを流したあとは `npm run smoke:fixtures:purge` で消すこと。
- journey 以外のスモークが作る作品・お題・ドラフト・同意の記録。
  人（ゲスト）は消えるが、行は残る。行ごと戻すのは journey だけの作り。

## 9. 既に残っていた2人の処理（2026-09-18）

D209 で journey スモーク由来と実証した2人を消した。
消す前に、18項目の指紋を1人ずつ照合し、**全部一致したときだけ**消す作りにした
（1つでも違えば何も消さずに止まる）。2人とも 18/18 一致。

照合した内容:
匿名である／停止・退会の途中でない／表示名を決めていない／電子メールを持たない／
認証の口でも匿名／回答はちょうど1件／ドラフト0／確定したお題0／作品0／同意0／
お気に入り0／いいね0／通報0／利用の記録はちょうど1件／
答えた作品の題名が `[検査用]` で始まる／その作品は削除済みかつ非公開／
その作品の持ち主はもう居ない／回答はその人が作られた10秒以内。

消したもの: この2人（`auth.users`）と、この2人の利用の記録2件。
消さなかったもの: この2人の回答2件。
理由は、回答の行は作品側の集計に関わる経路を持ち、
すでに削除済み・非公開・持ち主なしの検査用作品に付いているため、
消しても見え方は変わらず、触る危険のほうが大きいと判断した。
持ち主が外れた行はファネルのどの段にも入らない（5節）。
ほかの匿名ゲスト（36人）には触っていない。
