# 無人実行の記録の置き場

平日の日中に走る無人実行は、その日の記録をこのフォルダへ
`YYYY-MM-DD.md` という名前で書きます。1回の起動につき1ファイルです。

## なぜ分けているか

ユーザーと無人実行が、同じ時間帯に同じリポジトリを触ります。
両方が PROGRESS.md や docs/QUEUE.md のような「上に足していく」ファイルを書くと、
取り込むときに必ずぶつかります。2026-08-28 の夜に、記録ファイルの衝突が
実際に3回起きました（生き物の骨格ツールで2件、絵のお題当てサービスで3件、
人体フィギュアの実験では未記録があって取り込み自体ができず）。
コードそのものは一度もぶつかっていません。

そこで、無人実行の記録先を日付ごとの新しいファイルに分けました。
毎回ファイル名が違うので、原理的にぶつかりません。

## 誰が何を書くか

- PROGRESS.md — ユーザー専用。無人実行は読むだけで、書き換えない。
- docs/QUEUE.md — ユーザーが指示を書く場所。無人実行は読むだけ。
  終えた項目の完了印も、このフォルダの日付ファイルの側に書く。
- docs/PENDING.md — 無人実行が書き、ユーザーが回答を書く。
- docs/PROPOSALS.md — 無人実行が候補を書き、ユーザーが採否を書く。
- docs/auto/YYYY-MM-DD.md — 無人実行の記録。ユーザーは読むだけでよい。

## 日付ファイルに何を書くか

1. 今日やったこと。動作の変化が分かる言葉で。関数名の羅列にしない。
2. 注文書のどの項目を終えたか。項目の見出しをそのまま引く。
   終えていないなら、どこまで進んで何で止まったか。
3. 検証の結果。実行したコマンドと、その結果の数値。
4. 次に来る人が知っておくべきこと。前提が変わったなら、それを書く。
