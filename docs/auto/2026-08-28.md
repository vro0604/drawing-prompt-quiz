## 3. 検証の結果

この日 main へ入った変更について、実行したものと結果。

| コマンド | 結果 |
|---|---|
| `npm ci` | 終了コード 0 |
| `npm run typecheck` | 終了コード 0 |
| `npm run lint` | 終了コード 0 |
| `npm run build`（環境変数を1つも入れずに） | 終了コード 0 |

環境変数を空にしたビルドは、直す前は `/privacy` の生成で止まっていた。
`force-dynamic` を2枚に足すだけでは足りず、外したあとは `/saves` が
同じ理由で落ちる。根っこは `src/lib/supabase/server.ts` が
`assertSupabaseEnv()` を `cookies()` より先に呼んでいたこと。
`cookies()` を先に呼べば、その時点で Next.js が「この画面はビルド中に
描けない」と判断して降りるので、検査までたどり着かない。

環境変数を入れたビルドとも比べた。ルートの一覧（○ と ƒ の別）は
**前後で1行も変わらない。** もともと全画面が ƒ で、変わるのは
「環境変数が無いときにビルドが落ちるかどうか」だけ。

Vercel 側も success（Deployment has completed）。ただし
**プレビューの URL そのものはこの実行環境から開けない**（外向き通信の制限で
403 になる）ので、画面の目視確認はしていない。
