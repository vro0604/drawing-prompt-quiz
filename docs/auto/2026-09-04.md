# 2026-09-04 無人実行の記録

## 1. 今日やったこと

絵を見せたまま選択肢を出す画面を、外の決まりごとや実装がどう組んでいるかを調べ、
調査レポートを1本書いた。docs/RESEARCH/2026-09-04_選択肢の出し方.md 。

集めたのは9件。WCAG 2.2 の達成基準 2.5.8（押す対象の大きさ）、同 1.1.1 の試験に関する
例外、GOV.UK デザインシステムの「質問のページ」の型、同じくラジオの指針、
GOV.UK の実装が実際に取っている大きさ、H5P の Single Choice Set 、Moodle の多肢選択問題、
WAI-ARIA の作り方案内のキー操作、Material Web のラジオ。
9件すべて、公開リポジトリを複製して原本のファイルを直接読んだ。読んだ版の commit と
日付を各事例に書いた。

いまの回答画面が縦にどれだけの場所を取るかを、CSS の指定から自分で計算して3つの表にした。
選択肢1枠は 46px 、携帯では1問あたり 240px 、5問なら 1296px になる。携帯の画面の高さは
650px から 850px ほどなので、3問でも1画面に収まらず、下の問いに答えているあいだ
絵は画面の外にある。このサービスは絵だけを手がかりに当てる仕組みなので、これは飾りではなく
機能の欠けにあたる、というのが今日いちばん大きい発見。

末尾に判断が要る点を3件置いた。A が絵を見ながら選べるようにするか、B が選択肢に番号を
振るか、C が絵の代わりの文（alt）を題名のままにするか。

コードは一行も変えていない。書いたのは docs/RESEARCH/ と docs/auto/ の2か所だけ。

### 途中で1件、書いたものを取り下げた

判断が要る点の B は、最初「4択の並び順を出題のたびに入れ替えるか」で書いていた。
Moodle が入れ替えを既定にしているのを見て、こちらは並べ替えていないと考えたため。

書いたあとで確かめたところ、これは間違いだった。このサービスはすでに並び順を決めていて、
理由も書き残している。選択肢の並び（position 0〜3）は問題を作るときに1度だけ混ぜ、
そのあとは動かさない。supabase/migrations/20260803045329_quiz_choice_dedupe.sql の
265行目から267行目に「表示のたびに混ぜないのは、位置が毎回変わる選択肢が正解だと
分かってしまう、といった別の手がかりを与えないため」とある。

決着済みのことを判断待ちとして出すと、答える手間だけが増える。B は「番号を振るか」に
差し替え、並び順については事例7の側に「すでに決まっている」と書いた。
画面側のコードだけを見て「決まっていない」と判断したのが原因で、
データベース側の移行ファイルまで読めば最初から分かった。

## 2. 注文書のどの項目を終えたか

docs/QUEUE.md の項目には着手していない。このリポジトリの無人実行は CLAUDE.md の
「無人実行（クラウドのルーチン）の規約」で調査専用と決まっていて、QUEUE.md に並んで
いるのは実装の項目のため。

規約の「1回の起動でやること」に対しては、次のとおり。

- 起動時の確認: `git branch -r | grep auto/` は何も返さなかった。開いている PR は
  GitHub の一覧で4本（#2 、#5 、#6 、#7）だが、#5 #6 #7 の中身はすでに main に
  入っている（後述）。よって飛ばした項目は無い。
- 手順0（候補を出すか）: 出していない。docs/PROPOSALS.md に未選択（`[ ]`）の候補が
  P1 から P4 まで4件残っているため。規則どおり足していない。
- 手順1（題材を決める）: 採用済み（`[x]`）で未実施の候補は無かったので、自分で選んだ。
  docs/RESEARCH/ の既存2本（主色の決め方、当たり外れの見せ方）を読み、
  どちらも答えたあとの見せ方までしか扱っていないことを確かめたうえで、
  その手前の「答える前の画面」を選んだ。
- 手順2から4: 実施した。事例は9件で、規約の下限（5件）と上限（10件）の中に入っている。

## 3. 検証の結果

- ページを開いて読む道具（WebFetch）は使えなかった。試した2つの宛先（iridge.jp 、
  www.w3.org）がどちらも `EGRESS_BLOCKED` で拒否された。組織の通信方針による拒否なので
  迂回していない。過去2回（08-31 、09-02）と同じ結果。
- 検索（WebSearch）は通った。ただし検索結果の要約は事例の根拠に使っていない。
  どのリポジトリを当たるかを決めるところまでに使った。
- 公開リポジトリの複製（git clone）は通った。今日読んだのは7つ。
  w3c/wcag（2cde22e 、2026-08-28）、alphagov/govuk-design-system（a280397 、2026-09-03）、
  alphagov/govuk-frontend（fac3d6f 、2026-09-03）、
  h5p/h5p-single-choice-set（79a139f 、2026-08-31）、
  moodle/moodle（8eae8fc94 、2026-09-03）、w3c/aria-practices（7e4034b 、2026-07-22）、
  material-components/material-web（c05b4b2 、2026-08-28）。
  複製先はすべて作業用の一時領域で、リポジトリの中には置いていない。
- Moodle は全体が大きいので、`git sparse-checkout` で
  public/question/type/multichoice だけを取り出した。Moodle 5.x では
  question/ の位置が public/ の下へ移っていて、古い道筋（question/type/…）では
  1ファイルも取り出せない。次に読む人はここで詰まらないこと。
- 縦の長さは自分で計算した。Tailwind の既定値と
  src/app/works/[id]/_quiz.tsx:52-74 の指定から求めたもので、画面を実際に描かせてはいない。
- 変更範囲は `git status` で確かめた。docs/RESEARCH/ と docs/auto/ の下だけ。
