# 2026-09-11 無人実行の記録

## 1. 今日やったこと

日本語の書体 Noto Sans JP を実際にどう読み込むかを調べ、
docs/RESEARCH/2026-09-11_日本語書体の読み込み方.md に事例10件で書いた。

docs/PENDING.md の 3 番で「Noto Sans JP を読み込む」ことは 2026-08-27 に決まっているが、
決まっているのは書体の名前だけだった。どこから配るか、太さを何本使うか、
届くまでのあいだ何を出すかは、一度も調べられていなかった。その3つを埋めた。

分かったことのうち、実装の判断が変わりそうなものを3つ。

- 太さを2本（400と700）使っても、転送量は1バイトも増えない。今日の配信では
  太さ400と太さ700が同じ可変フォントのファイルを指していて、住所が一致した。
  ただし要求の書き方によって指定書き自体の重さは倍変わる（圧縮後で 60.7KB と 30.4KB）。
- 書体の分割は文字の種類順ではなく、使用頻度順だった。「ひらがなは1本で済む」という
  見込みは立たない。かぎ括弧「」も全角数字も、かなとは別のファイルに入っている。
- 画面に必ず出る短い言葉だけなら、text= という仕組みで 13KB 前後に落とせる。
  同じ字を通常の分割で賄うと 137KB かかるので、10分の1になる。

判断が要る点は3件立てた。どこから読むか、太さを何本にするか、届くまで何を出すか。
それぞれに選択肢と推奨と、そのまま返せる答え方を付けてある。

## 3. 検証の結果

コードは一行も変えていない。確かめたのは次の2つ。

- `git status` で、変更が docs/RESEARCH/ と docs/auto/ の下の新規2ファイルだけで
  あることを確認した。src/ 、test/ 、scripts/ 、設定ファイルは1バイトも動いていない。
- 調査の数値は、配布元へ実際に要求を出して数えた。主な実測は次のとおり。

| 測ったもの | 値 |
|---|---|
| Noto Sans JP の分割数（太さ1本あたり） | 124本 |
| 124本の合計 | 5,223,320 バイト（約 5.0MB） |
| かなの大半が入る1本 | 79,100 バイト |
| トップ画面の日本語132字に要る量 | 16本・約318KB |
| text= で18字を頼んだとき | 1本・13,176 バイト |
| 原本の可変フォント1本（google/fonts） | 9,589,900 バイト |
| @fontsource/noto-sans-jp 5.3.0 の展開後 | 76.7MB・2319ファイル |

開けなかったページは8つある（design.digital.go.jp 、developer.mozilla.org 、
fonts.google.com 、cdn.jsdelivr.net 、data.jsdelivr.com 、zenn.dev 、note.com 、
qiita.com）。いずれも組織の通信方針による拒否で、迂回はしていない。
このことは調査レポートの冒頭にも書いた。

そのため「実在のサービスが日本語の Web フォントを載せているか」を、動いている画面から
確かめることは今日はできなかった。事例10件はすべて、配布元そのものか、
公開されている原本のファイルから取っている。

## 4. 次に来る人が知っておくべきこと

- 前提が1つ変わった。この環境では WebFetch が全部塞がれているわけではない。
  fonts.googleapis.com は WebFetch でも curl でも通った。
  2026-09-04 と 2026-09-08 の記録は「試した宛先がどちらも遮断された」と書いているが、
  宛先によっては通る。塞がれているかどうかは、その日に試して確かめること。
- 公開リポジトリの複製は今日も通った。大きなリポジトリ（vercel/next.js 、
  google/fonts 、w3c/csswg-drafts）は、必要なフォルダだけを指定して浅く複製すれば
  数十秒で取れる。今日はこの方法で4つの原本を読んでいる。
- src/app/layout.tsx の注釈にある見積もり「使う字に応じて 100〜400KB ほど増える」は、
  今日の実測と桁が合っていた。ただし実測値は範囲の上寄り（215KB から 318KB）に出た。
  この注釈は訂正の必要が無いので、コードには触れていない。
- 調査が本流に取り込まれない状態が続いている。今日の時点で未取り込みが2本あり、
  今日のぶんを入れると3本になる。取り込みが遅れると、本流の docs/RESEARCH/ を
  読んだだけでは、どの題材が済んでいるかが分からない。
