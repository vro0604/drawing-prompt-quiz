## 2. 注文書のどの項目を終えたか

docs/QUEUE.md の項目には着手していない。このリポジトリの無人実行は
CLAUDE.md の「無人実行（クラウドのルーチン）の規約」で調査専用と決まっていて、
QUEUE.md に並んでいるのは実装の項目のため。

規約の「1回の起動でやること」に対しては、次のとおり。

- 手順0（候補を出すか）: 出していない。docs/PROPOSALS.md に未選択（`[ ]`）の候補が
  P1 から P4 まで4件残っているため。規則どおり足していない。
- 手順1（題材を決める）: 採用済み（`[x]`）で未実施の候補は無かったので、自分で選んだ。
  1度選び直している。経緯は上のとおり。
- 手順2から4: 実施した。事例は7件で、規約の下限（5件）と上限（10件）の中に入っている。

## 3. 検証の結果

- ページを開いて読む道具（WebFetch）は使えなかった。試した5つの宛先
  （news.ycombinator.com 、design.digital.go.jp 、design-system.service.gov.uk 、
  en.wikipedia.org 、zenn.dev）がすべて遮断され、
  `curl -sS -o /dev/null -w "%{http_code}" https://design-system.service.gov.uk/styles/colour/`
  は `CONNECT tunnel failed, response 403` を返した。組織の通信方針による拒否なので
  迂回はしていない。
- 一方、公開リポジトリの複製（git clone）は通った。今日読んだのは5つ。
  w3c/wcag（2cde22e）、alphagov/govuk-frontend（a3b356a）、
  digital-go-jp/design-tokens（cde7dfe）、h5p/h5p-multi-choice（f2cf935）、
  scribble-rs/scribble.rs（0003127）、twbs/bootstrap（12cb8b9）。
  複製先はすべて作業用の一時領域で、リポジトリの中には置いていない。
- GitHub の API 経由でファイルを読む道具は、このリポジトリ以外に使えない
  （`twbs/bootstrap is not configured for this session`）。複製なら読める。
- 色の比は自分で計算した。計算式は WCAG の相対輝度の定義どおり。
- 変更範囲は `git status` で確かめた。docs/RESEARCH/ と docs/auto/ の下だけ。

## 4. 次に来る人が知っておくべきこと

- 題材を決める前に、開いている PR の一覧を必ず見ること。docs/RESEARCH/ は
  main の側では空に見えるが、実際には 2026-08-31 の調査が PR #6 にある。
  今日はこれで半日ぶんを捨てた。
- この環境ではページを直接開けないが、公開リポジトリは複製して読める。
  デザインの決まりごとや色の値は、たいてい配布元のリポジトリに原本がある。
  検索結果の要約より、そちらを先に当たるほうが速くて確かだった。
- 今日のブランチは main ではなく a10718c（「docs: このリポジトリの無人実行を
  調査専用に変える」、2026-08-30）から切っている。origin/main もこの commit にある。
  クローン直後のローカルの参照は1つ古い 512caa3 を指していたので、
  次のルーチンは着手前に `git fetch origin main` をすること。
- docs/PROPOSALS.md に残っている P1 から P4 は、2026-08-27 に出された実装の候補で、
  無人実行が調査専用に変わる前のもの。いま採用しても無人実行は実装しない。
  規則の上ではこの4件が残っているあいだ新しい候補を足せないので、
  調査の候補を出させたいなら、4件を `[x]` か `[-]` で片付けるか、
  実装候補と調査候補を別の節に分ける必要がある。
- docs/PENDING.md の 2 番（主色）は PR #6 が出し直している。10 番（同じ直しの PR が
  3本）と 11 番（未 merge の PR があるときの動き）は未回答のまま。
  今日の取り違えは 11 番がそのままになっている結果でもある。
