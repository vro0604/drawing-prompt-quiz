## 5-4. この適用が、別の作業線へ与えた影響（実測。先に書いておく）

`20260908130000` を当てたことで、本番の最後の版番号がそこまで進んだ。
その結果、**それより古い版番号の未適用ファイルが `db push` から弾かれる。**

実測（`npm run db:status` の dry-run）:

```
Found local migration files to be inserted before the last migration on remote database.
Rerun the command with --include-all flag to apply these migrations:
  supabase/migrations/20260907120000_single_pass_draw_and_slot_redo.sql
  supabase/migrations/20260908120000_answer_analysis.sql
```

このうち `20260907120000` は前日（`20260908090000` の適用）から既にこの状態だった。
**今回あらたに加わったのは `20260908120000_answer_analysis.sql` の1本である。**

`20260908150000` `20260908160000` `20260909090000` は今回の版番号より後なので、
影響を受けない。

道は前回と同じ2つ。

1. 弾かれた側のファイル名を、本番の最後（`20260908130000`）より後の版番号へ
   付け替える。まだ一度も本番へ入っていないので、履歴と食い違わない。**推奨。**
2. `--include-all` を付けて押す。ただし `docs/db-workflow.md` はこの引数を
   禁止している（`applied/` の古いSQLを巻き込むため）。

どちらを採るかは、それぞれの作業線の判断。こちらでファイル名は変えていない。
なお `npm run db:apply:one` は版番号の順を見ないので、
**この状態でも1本ずつなら当てられる。**
