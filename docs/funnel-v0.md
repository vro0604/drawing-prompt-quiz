# 初回利用の進みぐあい v0（いまの表だけで測る）

最終更新: 2026-09-18 JST。測った本番の値は 2026-09-17T21:11Z 時点。
道具は `npm run db:funnel`（`scripts/db-funnel.sh` → `scripts/db-funnel.mjs`）。
数え方の本体は `scripts/funnel-query.mjs`、その数え方の試験は `test/tools/run.mjs`。

この工程で入れていないもの: 解析サービス、追跡用の cookie、閲覧の記録、
DB の migration、本番データの書き換え。すべて「すでに書き込みで残っている行」だけを読む。

---

## 0. いちばん大事な前提：分母は「トップを見た人」ではない

このサービスは、ページを開いただけでは利用者の行を作らない。
`ensureUserId()`（`src/features/auth/session.ts`）を呼ぶ操作で初めて匿名の利用者が発行され、
呼んでいるのは2か所だけ。

| 呼ぶ場所 | どの操作か |
| --- | --- |
| `src/app/play/actions.ts` | お題のドラフトを始める |
| `src/app/works/[id]/actions.ts` | 作品に答える・通報するなど |

つまり `profiles` の1行は「初めて何かを書き込んだ人」。
だから **「トップ閲覧者の何％が引いたか」は、いまのデータでは絶対に作れない。**
この文書と道具が出す率は、すべて「DB に現れた人」が分母。

同じ理由で、作る側の「人の発行 → ドラフト開始」は同じ操作なので必ず 100% になる。
落ちる場所を見るのは、その次の「お題を確定した」から。

## 1. 何が分かるか（正確 / 近似 / 分からない）

| 見たいこと | 判定 | 根拠（列・表） |
| --- | --- | --- |
| 初めてトップを見た | 分からない | 閲覧を記録していない |
| 「お題を引く」を押した | 分からない | 押しただけでは行が増えない（/play を開くだけ） |
| 「答える」を押した | 分からない | 同上（/works を開くだけ） |
| ゲストが発行された | 正確 | `profiles.created_at`（＋ `auth.users.is_anonymous`） |
| ドラフトを始めた | 正確 | `draft_sessions.created_at` |
| 最初のカードを引いた | 近似 | `draft_candidates.revealed_at` はあるが、ドラフト開始とほぼ同時。段としては使っていない |
| お題を確定した | 正確 | `prompts` の行そのもの（確定の RPC が1行 insert する） |
| お題のページまで進んだ | 分からない | 確定と同時に時計が動くだけで、ページを開いた記録は無い |
| 投稿画面へ進んだ | 分からない | 画面を開くだけでは行が増えない |
| 作品を投稿した | 正確 | `works.created_at`（`works.prompt_id` → `prompts.origin` で お題が先／絵が先 を判定） |
| 他人の作品を開いた | 分からない | 「次の作品へ」を押したときだけ `usage_events` に残る（開いた全部ではない） |
| 回答を送った | 正確 | `answers.created_at`（`answer_source='human'`） |
| 自分の作品に回答が付いた | 正確 | 自分の `works` に紐づく `answers`。人と仕組みは `answer_source` で分かれる |
| 結果を開いた | 正確（ただし2026-09-10 以降） | `works.result_seen_at`。開く RPC だけが書く。列ができたのが 2026-09-10 |
| 知らせを見ただけ | 別物として扱う | `notification_events.seen_at` はあるが、結果を開いたことにはしない |
| アカウント登録した（いまの状態） | 正確 | `profiles.is_anonymous = false` |
| いつ登録したか | 近似 | `terms_agreements.agreed_at` の最小（登録時に同意を取るため）。本番では登録4人中2人にしか記録が無い |
| ゲストから登録へ変わったか | 分からない | 変わった時刻を残す列が無い。`profiles.handle_updated_at` は本番では全員 null |

## 2. 測っている段

### 作る側・お題が先（prompt_first）

分母は「ドラフトから入った人」（最初の行動がドラフト開始だった人）。

人の発行 → ドラフト開始 → お題の確定 → 作品の投稿 → 人からの回答が付く → 結果を開く

判定は `prompts.origin`。`art_first` 以外（`draft` / `saved` / `daily`）をお題が先とする（spec 20-1 と同じ）。

### 作る側・絵が先（art_first）

別に数える。分母はその期間に発行された人ぜんぶ（入口では分けない）。

### 答える側

分母は「回答から入った人」。1回 → 2回 → 3回 → 5回以上。

「作品を開いたが答えなかった」は**測れない**（開いた記録が無い）。

### 登録

いま登録済みの人数、そのうち同意の記録がある人数、そのうち投稿した人数、
ゲストのままお題を確定した人数。

## 3. 数えられない理由が「消えた」ことにある行

退会・掃除で `profiles` の行が消えると、その人の行動の行は残るが持ち主の列が null になる
（外部キーが `set null`）。2026-09-17 時点の本番の実測:

| 表 | 行 | 持ち主が残っている行 |
| --- | --- | --- |
| works | 621 | 3 |
| prompts | 651 | 27 |
| answers | 389 | 17 |
| terms_agreements | 554 | 4 |
| draft_sessions | 40 | 40（人が消えると行も消えるため） |

この道具は「いま残っている人」しか数えない。**期間が長いほど母数は小さく出る。**
匿名のゲストは30日で掃除されるので、全期間の数字も実際より小さい。

### この数字をどう読むか

- **率として解釈しない。**どの期間も人数が1桁から数十で、しかも下で書くとおり
  検査（スモーク）が作ったゲストと本物の利用者を見分けられない。
- 1つだけ構造として言えるのは、**ゲストのままではどれだけ進んでも投稿に届かない**こと。
  投稿には登録が要るため（匿名ゲストは投稿できない。spec C3 / D27）、
  実測でもゲストの投稿は全期間0人、投稿1人はすべて登録済みだった。
- 「お題の確定 → 投稿」が全期間 5.3% なのは、ほとんどが検査で作ったゲストで、
  そもそも投稿する権限が無いため。**この数字を改善目標にしない。**

## 5. 検査（スモーク）由来の行が混ざる

- 登録した検査用の利用者は、電子メールの形で見分けられる
  （`scripts/_test-accounts.mjs`。3つの形を1か所で判定）。
- **匿名のゲストは見分けられない。**電子メールを持たないため（実測: `auth.users` 42人中、
  電子メールがあるのは4人だけ）。本番のスモーク（`smoke-journey`）は1回走るごとに
  ゲストを1人残す（`scripts/smoke-journey.mjs` の冒頭にそう書いてある）。
- したがって、いまの 24時間・7日の数字は**ほぼすべて検査由来**と見てよい。
  実利用の測定として使えるのは、限定公開を広げてからになる。

## 6. 2026-09-17 にゲストが2人増えた件の読み取り監査

問い合わせは読むだけ。削除も変更もしていない。個人情報（電子メール・IP・外部の識別子・
利用者の id）は取っていない。

| 見た項目 | 19:25:49Z の1人 | 19:29:17Z の1人 |
| --- | --- | --- |
| 作られた時刻 | 2026-09-17T19:25:49Z | 2026-09-17T19:29:17Z |
| ゲストか登録か | ゲスト（`auth.users.is_anonymous` も真） | 同じ |
| 電子メール | 無し | 無し |
| 片づけ道具の対象か | 対象外（電子メールが無いので形で判定できない） | 同じ |
| 作る行動 | ドラフト0・お題0・作品0 | 同じ |
| 答える行動 | 回答1件（プロフィール作成と同じ秒） | 同じ |
| ほか | `next_work_opened` 1件、同意0、知らせ0、いいね0、保存0 | 同じ |

判定: **テスト由来と確認。** 根拠は3つ。

1. `scripts/smoke-journey.mjs` の冒頭に「使い捨ての登録者2人、ゲスト1人…を残す」と書いてある。
   本番のスモークは1回走るごとにゲストを1人残す作りになっている。
2. 行動の形が、そのスモークのゲストの手順（共有 URL → 回答 → 結果 → 次の作品）と
   1件ずつ一致する。回答1件と `next_work_opened` 1件だけで、ドラフトも作品も無い。
3. 時刻が、この端末から本番へ流したスモーク2回と一致する。
   保存された画面の記録 `/tmp/dpq-journey` の最終更新は 2026-09-17T19:29:05Z で、
   回答の画面を撮った 12 秒後にこのゲストの回答が入っている。

同じ形のゲストは、この2人より前にも 18:03:01Z・13:54:58Z・13:50:46Z などにある。
これらも同じ手順の痕跡だが、**私が流したものだと時刻で確かめられるのは上の2件だけ**なので、
残りは「同じ形」とだけ書く。

## 7. いまのデータでは絶対に測れないもの（次に決めること）

| 測れないもの | 測るなら何が要るか |
| --- | --- |
| トップを見た人数 | 閲覧の記録。いまは1行も残していない |
| 「お題を引く」「答える」を押した数 | 押した時点の記録。いまは書き込みの直前まで何も残らない |
| 作品を開いたが答えなかった | 作品を開いた記録（`usage_events` は「次の作品へ」だけ） |
| 途中でやめた場所 | 画面ごとの記録 |
| ゲストから登録へ変わった時刻 | `profiles` にその時刻を残す列（migration が要る） |
| 同じ人が端末をまたいだか | いまの作りでは追えない（追わない方針） |

**この工程では1つも実装していない。**足すかどうかは、限定公開を広げて
実利用者が入ってから決める（そこまでは、どの数字も検査の痕跡が混ざる）。
